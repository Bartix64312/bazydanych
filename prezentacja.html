Struktura Danych

Baza danych została zaprojektowana w oparciu o model relacyjny. Główne obszary systemu to:

📚 Zasoby

  • Ksiazki: Centralny magazyn tytułów.
  • Filie: Fizyczne lokalizacje bibliotek.
  • Kategorie: Gatunki literackie.

👤 Użytkownicy

  • Uzytkownicy: Dane czytelników, loginy.

🔄 Procesy

  • Wypozyczenia: Łączy książkę z użytkownikiem.
  • Zwroty: Rejestracja oddania.
  • Rezerwacje: Kolejka oczekujących.

⚖️ Kontrola

  • Kary: Opłaty za przetrzymanie/zniszczenie.
  • Komentarze: System opinii.

Kluczowe Relacje

Baza zapewnia integralność danych poprzez zastosowanie kluczy obcych (Foreign Keys):

  • Relacja 1:N (Jeden do Wielu):
    • Jedna Filia posiada wiele Książek.
    • Jeden Użytkownik może dokonać wielu Wypożyczeń.
    • Jedna Kategoria może być przypisana do wielu Książek.
  • Zależność Logiczna:
    • Tabela Zwroty jest ściśle powiązana z tabelą Wypożyczenia. Nie można zwrócić książki, która nie została wypożyczona.
Przykład: Usunięcie użytkownika jest zablokowane, jeśli posiada on aktywne wypożyczenia lub naliczone kary (Constraints).

Automatyzacja: Wypożyczenie

Zastosowano Trigger, aby wyeliminować błędy ludzkie przy zmianie statusu książki.

Trigger: fn_after_wypozyczenie_insert

Działanie: W momencie dodania rekordu do tabeli wypozyczenia, system automatycznie zmienia status w tabeli ksiazki.

CREATE FUNCTION public.fn_after_wypozyczenie_insert() RETURNS trigger
LANGUAGE plpgsql
AS $$
BEGIN
    -- Automatyczna zmiana statusu na 'wypożyczony'
    UPDATE ksiazki 
    SET status = 'wypożyczony' 
    WHERE id_ksiazki = NEW.id_ksiazki;
    RETURN NEW;
END;
$$;

Automatyzacja: Zwrot

Analogiczny mechanizm działa przy oddawaniu książki, przywracając ją do obiegu.

Trigger: fn_after_zwrot_insert

Działanie: Po dodaniu wpisu do tabeli zwroty, system szuka powiązanej książki i zmienia jej status na "dostępny".

CREATE FUNCTION public.fn_after_zwrot_insert() RETURNS trigger
LANGUAGE plpgsql
AS $$
DECLARE
    wypozyczona_ksiazka_id INT;
BEGIN
    -- Pobierz ID książki z wypożyczenia
    SELECT id_ksiazki INTO wypozyczona_ksiazka_id 
    FROM wypozyczenia 
    WHERE id_wypozyczenia = NEW.id_wypozyczenia;
    
    -- Zmień status na 'dostępny'
    UPDATE ksiazki SET status = 'dostępny' 
    WHERE id_ksiazki = wypozyczona_ksiazka_id;
    RETURN NEW;
END;
$$;

Testy: Weryfikacja Wypożyczenia

Sprawdźmy, czy trigger działa poprawnie na przykładowych danych.

Krok 1: Sprawdzenie stanu przed

SELECT status FROM ksiazki WHERE id_ksiazki = 1;
-- Wynik: 'dostępny'

Krok 2: Wykonanie wypożyczenia

INSERT INTO wypozyczenia (id_osoby, id_ksiazki, data_wypozyczenia, planowana_data_zwrotu)
VALUES (1, 1, CURRENT_DATE, CURRENT_DATE + 30);

Krok 3: Weryfikacja automatyzacji

SELECT status FROM ksiazki WHERE id_ksiazki = 1;
-- Wynik Oczekiwany: 'wypożyczony' (Trigger zadziałał!)

Testy: Raportowanie i Analiza

Baza umożliwia tworzenie zaawansowanych raportów biznesowych.

Pytanie: Jakie są najpopularniejsze gatunki w bibliotece?

SELECT 
    k.nazwa_kategorii, 
    COUNT(w.id_wypozyczenia) as liczba_wypozyczen
FROM wypozyczenia w
JOIN ksiazki ks ON w.id_ksiazki = ks.id_ksiazki
JOIN kategorie k ON ks.id_kategorii = k.id_kategorii
GROUP BY k.nazwa_kategorii
ORDER BY liczba_wypozyczen DESC
LIMIT 5;
Zapytanie łączy 3 tabele, grupuje wyniki i sortuje je malejąco, dostarczając gotowe dane do analizy preferencji czytelników.
